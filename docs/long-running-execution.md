# Durable checkpoints for long-running execution

[Español](es/long-running-execution.md)

Use this protocol when a task can outlive one reliable agent context, cross a
compaction or handoff, or run long enough that conversational memory is not
acceptable evidence. Git remains the source history; a checkpoint records why
the work is in its current state and what must happen next.

## Contract

Every checkpoint is immutable, content-digested, linked to its predecessor, and
bound to all of these inputs:

- the unchanged repository-relative original plan and its content digest;
- the current Git revision and a content fingerprint of the non-ignored
  worktree, including untracked files and file modes;
- the global objective and next bounded objective;
- active invariants, with `holds`, `at-risk`, or `unknown` status and evidence;
- cumulative decisions and rationale;
- cumulative deviations from exact plan references;
- open risks and cumulative risk resolutions;
- test evidence generated by AAK, or an explicit reason why no test ran.

Checkpoint state is execution evidence. It never grants architecture
permission, accepts a risk, approves an ADR, waives a finding, or replaces
project policy.

## Start and checkpoint a task

Create the state draft inside the task's ignored runtime directory so editing
the draft does not change the worktree fingerprint:

```bash
mkdir -p .agentic/runtime/checkpoints/TASK-123
aak template checkpoint-state.json > \
  .agentic/runtime/checkpoints/TASK-123/draft-state.json
```

Fill every field from repository evidence and the original plan. Arrays are
explicit even when empty. Do not write conversational filler such as “all good.”
An invariant with uncertain truth uses `unknown`; a real risk remains open.
`create` rejects the distributed template's placeholders and blank required text.

Run tests through AAK when their result should be retained:

```bash
aak checkpoint run-test --task-id TASK-123 -- python3 -m unittest discover -s tests -v
```

AAK executes the argument vector without a shell and records the command, exit
code, timestamps, before/after workspace fingerprints, and streamed stdout and
stderr artifacts with their digests and sizes. Do not put tokens, passwords, or
other secrets in command arguments or test output.

Create the checkpoint only after the draft represents the exact segment:

```bash
aak checkpoint create \
  --task-id TASK-123 \
  --plan plans/original-plan.md \
  --state .agentic/runtime/checkpoints/TASK-123/draft-state.json
```

If no test is appropriate, make that absence explicit:

```bash
aak checkpoint create ... --no-tests-reason "Discovery-only segment; no executable behavior changed."
```

Failed or stale tests do not prevent checkpoint creation. Their state remains
visible so a later agent cannot inherit a false green result.

## Resume before continuing

Do not continue from conversational context alone. Run:

```bash
aak checkpoint resume --task-id TASK-123 --plan plans/original-plan.md
```

The command verifies the checkpoint chain, original plan digest, and exact
workspace, then emits the complete original plan followed by the complete
latest checkpoint. It writes a content-bound resume receipt. The next
checkpoint and any AAK-recorded test execution require that receipt.

AAK can prove that those inputs were supplied by the resume command. It cannot
prove private model cognition or that a person understood what was printed.

After resumption, normal worktree changes produce `IN_PROGRESS` and are valid.
Changes made before a receipt produce `UNRESUMED_WORKSPACE_DRIFT` and fail
closed. If legitimate external work changed the tree, reconcile it explicitly
instead of manufacturing a receipt or rewriting a checkpoint.

## State continuity

The chain enforces these transitions:

- the global objective and original plan identity cannot change within a task;
- decisions and plan deviations are cumulative and cannot disappear or be
  rewritten;
- a superseded decision keeps its original text and names its replacement;
- removing or rewriting an invariant requires a new decision that names it;
- an open risk cannot disappear without a cumulative resolution and evidence;
- test evidence can be consumed by only one checkpoint.

Start a new task chain when the global objective or original plan genuinely
changes. Do not disguise a new objective as checkpoint continuation.

## Verification and retention

Inspect current state or enforce it as a gate:

```bash
aak checkpoint status --task-id TASK-123 --plan plans/original-plan.md
aak checkpoint verify --task-id TASK-123 --plan plans/original-plan.md
```

`verify` reports:

- `CPK001`: schemas, content digests, immutable files, and chain links;
- `CPK002`: complete durable state;
- `CPK003`: unchanged original plan identity;
- `CPK004`: resume receipt before continuation.

The runtime directory is ignored by default. Preserve it across context resets,
machines, or ephemeral CI runners through an access-controlled task artifact.
Checkpoint JSON may contain product reasoning, risks, and filenames; apply the
same retention and confidentiality controls as other engineering evidence.
