# Human rationale and evaluation guide

This document explains why the architecture standard exists and how a team can
evaluate it. It does not add requirements for implementation agents.

## Why enforcement-oriented documentation

Long normative documents make every statement compete for the same attention.
The kit separates preventive decisions from mechanical checks and from human
explanation. The split is based on enforcement and reversal cost, not subject
matter or an aspirational folder tree.

## Adoption

An existing repository can adopt the kit incrementally: describe observed
boundaries, declare current decisions, expose violations, and use bounded
waivers for accepted migration risk. Teams avoid a cosmetic rewrite
whose only purpose is to resemble an example tree.

## Falsifiable evaluation

Useful evaluation compares agent outcomes with and without the kit across
placement accuracy, speculative structure, navigation effort, invalid
dependencies, unnecessary escalation, and evidence completeness. A more complex
context tool is justified only when measured results improve over simpler
repository search and deterministic indexes.

## Success

The kit succeeds when a new agent can locate ownership, make routine decisions
inside delegated authority, recognize genuinely new boundaries, retrieve
minimum sufficient context, validate its work, and hand the repository to
another agent without relying on conversation history.
